# sealed-egress

The only container on both the `apps` and `edge` networks of a deployment VM. It is the HTTP(S) proxy and the DNS server for every other container, and it enforces the per-caller allowlists that are part of the measured stack (spec 5.4, INTERFACES sections 12 and 14).

- Proxy (`listen.proxy`, default `:3128`): HTTP `CONNECT` tunnels and absolute-URI `http://` forwarding. Built on [stripe/smokescreen](https://github.com/stripe/smokescreen) embedded as a library. No TLS interception.
- DNS (`listen.dns`, default `:53`, UDP and TCP): answers A/AAAA only for names on the caller's allowlist, forwards them to `upstreamDns`, NXDOMAIN for everything else.
- Stats (`listen.stats`, default `:9100`): `GET /v1/stats` for `statsReaders` only, `GET /healthz` for anyone.

## Run

```
sealed-egress [-config PATH] [-auth-dir DIR]   # serve
sealed-egress [-config PATH] -check            # validate the config, print its sha256, exit
sealed-egress [-config PATH] -healthcheck      # probe the local /healthz (compose healthcheck)
```

The config path is `-config`, else `$SEALED_EGRESS_CONFIG`, else `/etc/sealed/egress.json`. `-auth-dir` (default `/run/sealed-egress/auth`) receives proxy credentials, see below. SIGINT or SIGTERM stops accepting, drains open tunnels for up to 8 seconds (inside Docker's default 10-second stop grace, so no `stop_grace_period` is needed) and logs a final counts line. Proxy environment variables are removed at startup (goproxy would otherwise chain through them).

Image: `docker build -f runtime/egress/Dockerfile .` from the repo root (multi-stage, pinned `golang:1.27.3-trixie` and `distroless/static-debian13:nonroot`, CGO off, `-trimpath -buildvcs=false`, empty build id). The license and notice files of every linked module and of Go are in `/licenses` (collected by `build/collect-licenses.sh`; a test checks it against `go version -m` of the built binary). The Dockerfile header shows the `buildx` flags (`SOURCE_DATE_EPOCH`, `rewrite-timestamp=true`) for a reproducible image digest. Binding port 53 as nonroot relies on Docker's default `net.ipv4.ip_unprivileged_port_start=0`; do not override that sysctl.

## Config

Canonical JSON (INTERFACES section 1), generated by the composer and measured. Parsing is strict: the bytes must be canonical (one trailing LF is tolerated, since a YAML block scalar `content: |` adds it; the printed sha256 is of the bytes without it), every key is required with exact case (arrays may be empty), unknown keys are errors.

```json
{"allowedPrivateCidrs":[],"callers":[{"allow":["sealed-key-broker-xyz.a.run.app:443"],"ip":"172.30.0.3","name":"sealed-agent","proxyAuth":true}],"listen":{"dns":":53","proxy":":3128","stats":":9100"},"statsReaders":["172.30.0.3"],"upstreamDns":["8.8.8.8:53"]}
```

- `callers[].ip` is the caller's fixed container IP; the source IP of each connection selects the caller. Unknown sources are denied.
- `callers[].proxyAuth` (optional, only ever `true`; omit it otherwise): the caller must also present its proxy credential. Use it for the platform sidecars (sealed-agent, sealed-mpp-payer, Caddy).
- `callers[].allow` entries are `host:port`, `*.domain:port` (exactly one extra label, never the apex) or `a.b.c.d:port`. Hosts are lowercase ASCII (punycode), at least two labels, no trailing dot. Only listed ports are reachable. Wildcards over an ICANN public suffix (`*.com`) and IPv6 literals are rejected. Raw IP entries must be public or inside `allowedPrivateCidrs`. Entries must be unique per caller.
- `allowedPrivateCidrs` may only open ranges inside 10/8, 172.16/12, 192.168/16, 100.64/10 (CGNAT) and fc00::/7 (ULA). Entries must not overlap each other and must not lie inside the VM's own networks (172.30.0.0/24, 172.31.0.0/24). A broader range such as 172.16.0.0/12 is accepted, but the VM networks inside it stay denied.
- `upstreamDns` is 1 to 8 `ip:port` values.

The `policy` package has no proxy or DNS dependencies, so the composer can build configs with `policy.Config`, `policy.EncodeCanonical` and `(*policy.Config).Validate`. Its CJSON checker runs the shared vectors in `runtime/composer/testdata/cjson/vectors.json`.

## Proxy credentials (`proxyAuth`)

Docker gives containers CAP_NET_RAW by default and the bridge has no ARP or IP anti-spoofing, so an app container could pose as 172.30.0.3. For `proxyAuth` callers the source IP only selects the allowlist; the request must also carry the caller's token.

- At startup egress writes one random token per `proxyAuth` caller to `<auth-dir>/<caller>/token` (64 hex characters, no newline, mode 0444), reusing a valid existing token so restarts do not break the caller. Tokens never appear in the config (the compose is public through `/attest`) or in logs.
- Proxy requests: `Proxy-Authorization: Basic base64(<caller>:<token>)`, which HTTP clients send for a proxy URL `http://<caller>:<token>@172.30.0.2:3128`. Missing or wrong credentials get `407` with `Proxy-Authenticate: Basic realm="sealed-egress"` and `X-Sealed-Egress: auth-required`, and count as `unauthenticated:0`. The header is stripped before plain HTTP requests are forwarded.
- `GET /v1/stats` from a reader that is a `proxyAuth` caller needs `Authorization: Bearer <token>`.
- Composer wiring: one named volume mounted read-write at `/run/sealed-egress/auth` in sealed-egress (the image creates that directory owned by nonroot, so a new volume inherits the owner), and read-only in each `proxyAuth` caller with `volume.subpath: <caller>` (or the whole volume where subpaths are unsupported; only platform sidecars ever mount it). The caller reads its token at startup, and re-reads it after a 407.
- DNS cannot carry credentials. A spoofer can only resolve names already on that caller's allowlist and receives no answers without also poisoning ARP. It can use up that caller's DNS query budget (UDP needs no reply), which does not affect proxied traffic since the proxy resolves names itself, and with ARP poisoning it could hold the caller's reserved connection slots or simply drop its packets. Credentials protect what a spoofer can reach, not availability, which is why app services should also run with `cap_drop: [NET_RAW]`.

## Destination checks

Applied after resolution to every address, and again just before the dial; only the checked IP is dialed (DNS rebinding safe).

| always denied | denied unless in `allowedPrivateCidrs` |
|---|---|
| metadata (169.254.169.254, fd20:ce::254, fd00:ec2::254), loopback, link-local (169.254/16, fe80::/10), 0/8, multicast, 240/4, 192.0.0.0/24, 198.18.0.0/15, 192.88.99.0/24, NAT64 (64:ff9b::/96, 64:ff9b:1::/48), 6to4, Teredo, IPv6 benchmarking and ORCHID, IPv6 outside 2000::/3, the VM networks 172.30.0.0/24 and 172.31.0.0/24 (bridge gateways included), the networks of the egress container's own interfaces, and its own addresses | 10/8, 172.16/12, 192.168/16, 100.64/10, fc00::/7 |

The TEST-NET documentation ranges are left public: they are not routed anywhere and the tests use them as fixtures.

Absolute `https://` URLs (which would make the proxy speak TLS for the client) and client-chosen upstream proxies (`X-Upstream-Https-Proxy`) are refused.

Denials are `403 Forbidden` with header `X-Sealed-Egress: blocked`. Upstream failures stay `502`/`504` and are not counted as blocked.

## Per-caller limits

There is no global limit one app could exhaust; every limit is per caller (unknown sources share one bucket). Defaults (`limits.Defaults`):

| limit | default | over the limit |
|---|---|---|
| open proxy connections reserved for each caller | 32 | (always available) |
| open proxy connections per caller | 512 | `429`, `X-Sealed-Egress: limited`, before the request is read |
| shared pool borrowed beyond the reserved share | 2048 | as above |
| connections from unknown sources | 16 | as above |
| proxy connection lifetime | 12 h | closed, even if busy |
| proxy requests per caller | 100/s, burst 200 | `429`, counted as `rate-limited:0` |
| DNS queries per caller | 100/s, burst 200 | REFUSED, counted as `rate-limited:53` |
| DNS queries per caller waiting on the upstreams | 32 | REFUSED, counted as `rate-limited:53` |

A connection holds its slot until it closes, which covers CONNECT tunnels, in-flight plain HTTP requests and idle keep-alives. So sealed-agent and the payer always keep 32 connections each, whatever the apps do. The proxy's own resolver caches positive answers for at most 30 seconds (less if the TTL says so), so proxying keeps working for recently used names if a DNS flood gets the VM rate-limited upstream. The DNS server path is not cached.

## DNS answers

| query | answer |
|---|---|
| A/AAAA for a name on the caller's allowlist (any port) | forwarded; addresses in denied ranges are stripped and counted as blocked |
| other types for an allowed name | NOERROR, no records (never forwarded) |
| ANY or a non-IN class for an allowed name | REFUSED, counted |
| any type for any other name | NXDOMAIN, counted |
| any query from an unknown source | REFUSED, counted |
| any query over the caller's rate or in-flight limit | REFUSED, counted |

UDP replies are truncated to the client's buffer (512 bytes, or its EDNS0 size up to 4096) with TC set, so the client retries over TCP. Upstream answers with TC are retried over TCP. Upstream servers are tried in rotation with failover.

## Stats

```json
{"since":1730000000,
 "allowed":{"api.example.com:443":12,"*.cdn.example.net:443":3},
 "blocked":{"unlisted:443":2,"ip-metadata:80":1,"unlisted:53":40,"rebind.example.com:443":1},
 "callers":{"scraper":{"allowed":{...},"blocked":{...}}}}
```

`allowed` and `blocked` aggregate all callers (the INTERFACES shape); `callers` breaks them down by caller name (`(unknown)` for unknown sources).

The counts leave the VM (sealed-agent forwards them in `/v1/health`), so P5 requires keys to be content-free. Every key is either one of the caller's allowlist entries, which the platform already knows from the measured config, or a word from a fixed vocabulary. No hostname, label, IP address or port number chosen by a container appears unless the allowlist already lists it:

| key | meaning |
|---|---|
| `<entry>` (allowed) | the allowlist entry that matched (`*.cdn.example.net:443`, not the full host) |
| `<entry>` (blocked) | matched, but resolved to a denied address (rebinding) |
| `<pattern>:<port>` | name on the allowlist, port not allowed for it (`api.example.com:other`) |
| `<pattern>:53` | DNS: ANY, a non-IN class, or answers stripped for pointing at denied ranges |
| `unlisted:<port>` | any hostname not on the caller's allowlist (`unlisted:53` for DNS) |
| `ip-<class>:<port>` | raw IP not on the allowlist: `ip-public`, `ip-private`, `ip-metadata`, `ip-loopback`, `ip-link-local`, `ip-vm-internal`, `ip-reserved`, `ip-multicast`, `ip-unspecified`, `ip-ipv4-embedding` |
| `invalid:<port>` | destination is not a valid host |
| `unauthenticated:0` | missing or wrong proxy credential |
| `rate-limited:0`, `rate-limited:53` | proxy request or DNS query over the caller's limits |
| `other:0` | overflow of the per-caller key cap |

`<port>` is the requested port when it is 80, 443 or a port somewhere in that caller's allowlist, and `other` otherwise. Keys that are allowlist entries are never capped (the config bounds them); other keys are capped at 256 per caller and verdict, after which they count under `other:0`. With the fixed vocabulary only very large configs can reach that cap.

What remains is the counts themselves: a container can still signal through how often it is blocked, at one request per unit. P5 explicitly allows counts. Finer detail (which domain an app tried) is not available anywhere, by design; customers find blocked destinations from the app's own errors.

The same counts (for the last interval) are logged once a minute as one JSON line, `{"msg":"egress counts","interval_s":60,"allowed":n,"blocked":m,"callers":{...}}`. Smokescreen's per-request logs are discarded.

## Tests

```
go test -race ./runtime/egress/...
go test -tags smokescreen_no_prometheus ./runtime/egress/...   # the image's build tags
go test -short ./runtime/egress/...                            # skips the image license check, which builds the binary
```

Unit tests cover config validation, matching, the stats key grammar, IP classes, the shared CJSON vectors, stats, limits, credentials, the upstream client and cache, the DNS server and the license collector. `egress_test.go` runs the whole service on 127.0.0.1 random ports with local HTTP and HTTPS upstreams and a fake upstream DNS server: A8 cases (allowed hosts, non-allowlisted hosts, raw IPs, metadata, rebinding over CONNECT and plain HTTP, random-subdomain lookups), chosen names and IPs never reaching `/v1/stats`, one caller unable to starve sealed-agent, per-caller request rates, spoofing a `proxyAuth` caller's IP, a blocked second request on a keep-alive connection, self-connection and local networks, logs, shutdown. Three test-only hooks in `egress.Options` make that possible on one host: `SourceIP` (maps client source ports to caller IPs), `Dial` (routes dials for fake public IPs to the local servers, after every check) and `LocalSubnets` (so the test host's own interfaces do not decide results). Production leaves all three nil.

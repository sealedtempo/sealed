# runtime/caddy

`Caddyfile.tmpl` and `payment-needed.html`, embedded by the Go package in this directory and rendered by the composer (`runtime/composer`). Both Caddyfile variants and the page are passed to the stack as inline compose configs, so they are part of stackHash. The full contract (gate, routes, admin socket) is in `runtime/composer/README.md`, section Caddy.

- Normal variant: one site per route hostname plus the attest site. `gate` routes ask sealed-agent first with `forward_auth sealed-agent:7070 { uri /v1/gate?route=<route> }` (D-044); the agent's `Set-Cookie` on a 200 is copied to the client response, Basic credentials of the gate user `sealed` are stripped before the app (when the agent's 200 carries `X-Sealed-Gate-Strip-Authorization: 1`, and when the header matches `^[Bb][Aa][Ss][Ii][Cc][ \t]+c2VhbGVkO`, spaces or tabs as the agent accepts; review C-3), and any other `Authorization` header (an app's own Bearer token) passes through. Clients cannot supply `X-Sealed-Gate-Set-Cookie` or `X-Sealed-Gate-Strip-Authorization`: both are removed before `forward_auth`, and neither reaches the app. Any non-2xx answer from the agent (401 with a Basic challenge, 503 while the app's bootstrap runs) reaches the client unchanged. `bearer-passthrough` routes send `Authorization: Bearer` requests straight to the app and gate everything else; `public` routes are open. Every proxied app request loses the `sealed_gate` cookie. The template renders any mode; the composer allows `bearer-passthrough` only for `llm-gateway` route `gateway` and `public` only for `inference-relay` route `relay`, so every other app UI is gated. Caddy holds no secret.
- Attest site: `/` and `/attest` proxy `sealed-agent:7070/attest` (public); routes with `on_attest_host` (the relay's `/v1`, D-045) are served next to it on the same origin and certificate; anything else is 404.
- Each app handle body is a `route` block, because inside a plain `handle` Caddy runs same-named directives that have a matcher before those that have none.
- Admin API: `unix//run/sealed/caddy-admin/admin.sock|0660` on a tmpfs owned by 10001:10001 with the setgid bit; Caddy gets `group_add: ["10001"]`, so the socket belongs to the agent's group and the agent needs no root helper.
- The Caddy container drops every capability except `NET_BIND_SERVICE` (the image's `caddy` binary carries it as a file capability, and exec fails without it in the bounding set) and runs with `no-new-privileges`.
- Payment-needed variant: every app host serves the static page with status 402, bearer API calls and attest-host routes get a plain 402; `/attest` is unchanged. sealed-agent switches by `POST /load` (`Content-Type: text/caddyfile`) on the admin socket, and restores by loading the normal file.

Pinned image: `caddy:2.11.7-alpine` (index `sha256:eb4d35b7...`, Apache-2.0), mirrored to the catalog registry; see `runtime/composer/runtime-images.json`. The page uses only plain product wording, no external resources and no em-dashes. Tests: `go test ./runtime/caddy`, plus the real-Caddy run in `runtime/composer` (`SEALED_CADDY_BIN`, checked with Caddy v2.11.7).
